## 1. 背景与目标

为 zsagent 知识库平台 Agent 提供前端管理界面，覆盖 BRD 中 MVP 阶段的：
- **基础对话界面**（智能问答：多轮对话、引用溯源、答案反馈）
- **知识管理界面**（目录管理、文档管理、文件上传）

当前后端已具备完整的 agent / knowledge（目录+文档）/ file 三组 Web 接口，前端的目标是把这些接口**界面化**，形成可直接使用的中后台产品。

## 2. 技术选型

### 2.1 基座选型

- **基座**：vben-admin v5，使用官方主推的 **`web-antd`** 变体（Ant Design Vue）。
- **理由**：官方默认与文档/demo 对焦、维护最积极；monorepo 共享内核（权限、mock、主题、i18n），功能能力与 web-ele 等其他变体一致，后续如需切换组件库成本可控。
- **技术栈**：Vue 3 + TypeScript + Vite + Ant Design Vue + Pinia + Vue Router，基于 vben 内置的 `@vben/request`。

### 2.2 认证与用户

- 当前阶段**不建设真实权限认证体系**：
  - `accessMode: 'frontend'`，登录走 vben demo mock（默认管理员账号）跑通壳子；
  - 页面路由暂不配置 `meta.authority` 过滤，全部可见。
- 定义前端常量 `DEFAULT_USER_ID`（如 `user_123`），所有需要 `userId` 的接口统一注入，后续接入 token/SSO 后再替换。

## 3. 后端接口盘点（前端功能范围）

前端页面核心功能对应 `adapter` 模块下 `web.agent` / `web.knowledge` / `web.file` 三组 Web 接口，共 19 个端点。

### 3.1 Agent 智能问答

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/agent/ask-question` | SSE 流式问答（body: userId, conversationId, question） |
| POST | `/api/v1/agent/submit-feedback` | 答案反馈（type: USEFUL/NOT_USEFUL，NOT_USEFUL 可带 reason） |
| GET | `/api/v1/agent/get-conversation` | 对话详情（消息 + 来源引用 + 反馈状态） |
| GET | `/api/v1/agent/list-conversations` | 会话列表（分页） |

### 3.2 File 文件

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/file/upload` | multipart 上传（part 名 `file`），返回 `filePath` 相对路径 |

### 3.3 Directory 目录

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/directory/create` | 创建目录 |
| POST | `/api/v1/directory/rename` | 重命名目录 |
| POST | `/api/v1/directory/move` | 移动目录 |
| POST | `/api/v1/directory/delete` | 删除目录 |
| GET | `/api/v1/directory/tree` | 完整目录树（含 documentCount） |
| GET | `/api/v1/directory/list-children` | 子目录列表（懒加载） |

### 3.4 Document 文档

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/document/create` | 创建文档（**先上传拿 filePath**，再带元数据创建） |
| POST | `/api/v1/document/update-metadata` | 更新元数据（title/tags/visibility，**不产生新版本**） |
| POST | `/api/v1/document/update-content` | 更新内容文件（**产生新版本并触发 ETL**） |
| POST | `/api/v1/document/delete` | 删除文档（移入回收站） |
| POST | `/api/v1/document/restore` | 恢复文档 |
| POST | `/api/v1/document/rollback` | 回滚到历史版本 |
| GET | `/api/v1/document/get-document` | 文档详情（**仅元数据，无正文**） |
| GET | `/api/v1/document/list-documents` | 分页列表（按 directoryId/keyword/status 筛选） |
| GET | `/api/v1/document/list-versions` | 版本历史（versionNumber/fileSize/changeLog） |
| GET | `/api/v1/document/get-etl-status` | ETL 解析状态（轮询） |

> 关键事实：绝大多数请求体携带 `userId`（当前无鉴权，body 明文传入）。

## 4. 工程搭建

### 4.1 目录位置

在仓库根下新建 `frontend/` 目录，与 `app` / `bootstrap` / `conf` / `test` 平级，Node 工程与 Maven 工程互不干扰。

```
frontend/
└── apps/web-antd/        # vben web-antd 变体（裁剪 demo 后）
```

### 4.2 关键配置

| 配置项 | 取值 |
|---|---|
| 访问模式 | `accessMode: 'frontend'`（无动态菜单） |
| 登录 | vben demo mock（admin 账号），不做真实权限 |
| `userId` | 常量 `DEFAULT_USER_ID`，全局注入 |
| Vite proxy | `/api` → 本地 zsagent 后端地址，规避 CORS |
| 生产 API | `.env.production` 配置 `VITE_GLOB_API_URL` 指向真实后端 |

### 4.3 菜单结构

```
智能问答  /agent/chat
知识管理  /knowledge
 ├─ 目录管理  /knowledge/directory
 └─ 文档管理  /knowledge/document
```

## 5. 页面与功能设计

### 5.1 智能问答 /agent/chat

独立布局（非 CRUD 页面）：

- **左栏会话列表**：`list-conversations` 分页加载；点击会话 → `get-conversation` 加载消息。
- **新建对话**：前端 `crypto.randomUUID()` 生成 `conversationId`，立即进入空对话界面，零往返。
- **消息区**：
  - USER 气泡靠右、ASSISTANT 气泡靠左；
  - 流式回答逐字渲染 + 流式光标；
  - **停止生成**：AbortController 中断 SSE 请求。
- **来源引用**：助手消息下方来源卡片（documentTitle + contentSnippet tooltip）。
- **反馈**：👍/👎 按钮，NOT_USEFUL 时弹出原因输入框。
- **空态**：欢迎语 + 推荐问题。

### 5.2 目录管理 /knowledge/directory

- 左侧目录树：默认 `tree` 全量加载（含 `documentCount`），数据量大时改用 `list-children` 懒加载。
- 节点操作：新建子目录、重命名、移动（弹目录树选择器）、删除（确认框）。
- 对应 `create` / `rename` / `move` / `delete` 四个命令接口。

### 5.3 文档管理 /knowledge/document

核心 CRUD + 版本/回收站/ETL 流程：

- **筛选栏**：目录（树下拉）、关键字（title/tags 模糊）、状态（正常/回收站/ETL 状态）。
- **表格列**：标题、所属目录、格式、大小、标签、可见范围、状态、ETL 状态、当前版本、更新时间、创建人、操作。
- **新建文档**（弹窗）：
  1. 选择文件 → `/file/upload` 获取 `filePath`；
  2. 填写 title（缺省取文件名）、选择目录、tags、visibility（+ visibleTo）；
  3. `/document/create`。
- **编辑元数据**：修改 title/tags/visibility → `update-metadata`（不产生新版本）。
- **更新内容**：重新上传文件 → `update-content`（填写 changeLog）。
- **版本历史**（抽屉）：`list-versions` 展示版本列表（版本号/大小/变更说明/时间）→ `rollback` 回滚。
- **回收站**：`status` 筛选已删除文档 → `restore` 恢复。
- **ETL 状态**：create / update-content 后轮询 `get-etl-status`，展示解析中/成功/失败原因。

### 5.4 文件上传模块

- 封装独立 API 模块，被文档管理的新建/更新内容复用；
- 当前不做独立上传页面（如需批量上传后续再加）。

## 6. 前端 API 层与类型

位于 `frontend/apps/web-antd/src/api/`：

```
api/
├── agent/      # askQuestion(SSE), submitFeedback, getConversation, listConversations
├── directory/  # create/rename/move/delete/tree/listChildren
├── document/   # create/updateMetadata/updateContent/delete/restore/rollback/get/list/listVersions/getEtlStatus
└── file/       # upload
```

- 类型定义对齐 facade DTO 字段：
  - `Document`：documentId, title, summary, format, fileSize, directoryId, directoryName, tags[], visibility, status, etlStatus, etlErrorMessage, currentVersion, creator, createTime, updateTime
  - `Directory`：directoryId, parentId, name, sortOrder, children[], documentCount
  - `DocumentVersion`：versionId, versionNumber, fileSize, changeLog, creator, createTime
  - `Conversation` / `Message` / `SourceReference`：对齐 agent 模块 DTO（conversationId/title、messageId/role/content/sources/feedback、documentId/documentTitle/contentSnippet/score）
- 统一解包 `RespData<T>`；SSE 单独封装 `useSse` composable。

## 7. 关键技术要点

- **SSE over POST**：原生 `EventSource` 仅支持 GET，须用 `fetch` + `ReadableStream` + `TextDecoder('utf-8')`，按空行分帧解析 `data:` 行，以 `event: done` 判定流结束；配合 AbortController 支持停止生成。
- **流式 markdown 增量渲染**：边收边渲染，长答案用 rAF / 定时器节流，避免卡顿。
- **上传**：multipart（part 名 `file`），与 JSON 请求分开处理，返回 `filePath` 后拼接到文档创建/更新流程。
- **目录树**：AntD `a-tree`，懒加载节点在展开时按需调用 `list-children`。
- **请求统一走 `@vben/request`**：需确认在无权限模式下其 token/401 拦截器不阻塞业务请求。

## 8. 与后端协作的缺口

| # | 缺口 | 影响 | 建议 |
|---|---|---|---|
| 1 | `get-document` 仅返回元数据，无正文/下载接口 | 文档管理"详情/预览"无法实现 | 后端补下载或预览端点（BRD"查看原文"需求） |
| 2 | `SourceReferenceDTO` 缺 `url` / `chunkId` 字段 | 对话页"查看原文"跳转不可用 | 后端补字段或返回完整跳转 URL |
| 3 | 无 create-conversation 接口 | 会话标题来源未确认 | 确认后端是否在首条消息时自动生成 title |
| 4 | `visibility`（public/department/specific）+ `visibleTo` 对象列表 | 前端下拉数据来源待定（部门列表） | 确认部门数据来源 |
| 5 | 全项目无 CORS 配置 | 生产独立部署跨域失败 | 开发期 Vite proxy 规避，生产补 CORS 或网关转发 |

## 9. 里程碑

| 阶段 | 内容 | 依赖 |
|---|---|---|
| M1 基座 | vben 拉取与裁剪、Vite proxy、固定 admin、菜单骨架 | 无 |
| M2 智能问答 | chat 页全流程（SSE 流式/历史会话/新建对话/反馈/来源） | 后端已有，无阻塞 |
| M3 知识管理 | 目录树 + 文档 CRUD + 文件上传 + 版本/回滚 + 回收站 + ETL 轮询 | 需确认缺口 1（正文预览） |
| M4 打磨 | 权限接入（vben RBAC）、缺口 2/3/4 补全 | 后端 auth 模块 |
